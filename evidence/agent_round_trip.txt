# The agent-facing capability interface, end to end (stretch goal S1, R-M7-1)

`uv run python scripts/watch_agent_call.py`, transcript as printed.

`cua catalog --json` is shelled out for real; its output is sent as `tools` on a
Messages API call to claude-sonnet-5; the model's `tool_use` blocks are resolved
back to their artifact and dispatched to the M3 replay engine; the results come
back as `tool_result` blocks the model answers from. Nothing here is staged.

Two things in this transcript are worth reading closely.

  * The model called the tool TWICE -- once with 99999 and once with 12345 --
    because the capability's description is the discovery goal verbatim, and that
    goal contained a negative-path probe. It spent a replay on a question nobody
    asked. This reproduced on every run. See REPORT.md section 7: the defect is
    the recorder conflating two audiences, and it is reported rather than patched
    behind the content hash.

  * `member_name` reaches the model as `<redacted>` while the engine read
    "Dana Whitfield". A tool result is a prompt on the caller's next turn, so it
    is rendered from `evidence_outputs`. The cost is visible and real: a
    capability whose purpose was to read a name could not be answered this way.

THE SAME INTERFACE, WITH AN ARGUMENT THE ARTIFACT REFUSES
`uv run python scripts/watch_agent_call.py --bad-argument`

Defence in depth, and the layers are independent. The model declines first --
the `^\\d{5}$` is in the schema it was handed, so it never makes the call. The
dispatch path is then given the call it would have had to make, and refuses it
in 34 ms with no browser navigation, as a tool result the model could act on.
